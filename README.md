# 过路行人检测

第一次自己完整跑一遍 YOLOv5，把数据集怎么来的、训练参数和最后的结果记一下，免得过几天就忘了。

## 数据

视频是自己在网上搜的一段行车记录仪片段，1280x720，9.7 秒左右。用 OpenCV 隔几帧截一张，最后留了 70 张图。

画面里主要就是过马路的那两个人，一个穿黑衣服的女士，一个穿橙色马甲的男的，所以只标了一个类：person。

标注是先拿预训练的模型自动标了一遍，再按框的高度筛，把远处的人和坐在店门口的人去掉，只留这两个。70 张图一共 133 个框，训练 56 张、验证 14 张，8:2 随机分的（seed 0）。

数据集没有传上来，图片和 txt 都在本地，照上面这个抽帧和标注的规则重新弄一遍就能复现。

## 训练

电脑是 RTX 5060 Laptop 8G，Python 3.10，PyTorch 2.7.0+cu128，YOLOv5 用的 v7.0。

参数基本是照着教程填的，没怎么调：

```bash
python train.py --img 640 --batch 16 --epochs 100 --data person.yaml \
  --weights yolov5s.pt --workers 0 --device 0
```

100 轮大概三分钟就跑完了，把图片缓存到内存里会快很多。

## 结果

验证集 14 张图，28 个框：

```text
P 0.991    R 1.000    mAP@0.5 0.995    mAP@0.5:0.95 0.843
```

数字看着挺好看，但验证集和训练集是从同一段视频里抽的，很多帧只差一点点，所以只能说明流程跑通了，真换个场景估计没这么高。

推理命令：

```bash
python detect.py --weights best.pt --source video.mp4 \
  --conf-thres 0.35 --iou-thres 0.45 --line-thickness 3 --hide-labels
```

原视频不到 10 秒，提交要求 10–30 秒，就把输出按 20fps 重写了一遍，变成 14.55 秒，画面会稍微慢一点。

## 踩的坑

- 傍晚光线暗，人又小，远处经常漏检。后来把抽帧范围换到 160–240 帧这一段才好一些。
- 两个人并排走、贴得很近的时候会框成一个框，70 帧里有 7 帧是这样，暂时没解决。
- 筛背景行人的阈值调了好几次，低了会把店员也标进来，高了又会把主角漏掉，最后用的 14% 图高。
- Windows 上 dataloader 多进程一直报错，查了半天改成 workers=0，又把标签缓存那块改成串行才跑起来。
- 验证集 mAP 偏高，跟相邻帧太像有关，自己心里有数就行，不能当真。
